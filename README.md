# 比赛管理系统 · 追分版

面向小型团队的羽毛球、乒乓球比赛现场，提供从赛程安排、实时计分到结果汇总的一站式管理。系统以「追分」累计方式记分，覆盖分组名单、出场安排、赛程发布、现场计分、比赛竞猜与积分榜单，让组织者轻松办赛，让参赛者与观众随时掌握赛况。

**适用场景**：部门团建、班级联赛、俱乐部内部对抗等小型团队赛事——队伍有限、场次集中、现场计分、赛后即时出榜。

**核心功能**：赛程统一管理（分组、阵容、对阵发布）· 现场实时计分（逐分记录、误记回退）· 积分自动汇总（榜单生成、冠军锁定）· 比赛竞猜互动（冠军与小局竞猜，提升参与感）。

**使用价值**：一部手机即可完成现场计分，队员与观众通过浏览器随时查看实时比分与榜单；组织更省心、过程更透明、结果更可信。

## 功能结构

系统按「身份入口 → 业务功能 → 支撑能力 → 运行底座」四层组织：

| 层级 | 组成 | 作用 |
| --- | --- | --- |
| 身份入口 | 选手 / 队长、观众、老师 | 区分权限，无注册密码也能定位到独立账号 |
| 业务功能 | 小组名单、出场安排、赛程对阵、裁判计分、比赛竞猜、积分榜单 | 承载比赛从准备到结算的完整流程 |
| 支撑能力 | 实时同步、权限与防篡改、自定义对局 | 保证多人同时查看时数据一致、操作可信 |
| 运行底座 | `backend/`、`frontend/`、SQLite 与公网隧道 | 提供可移植的运行环境和远程访问能力 |

### 1. 身份入口

- **选手 / 队长**：用真实姓名 + 本人 4 位验证码登录（初始 `1234`，可自行修改），名单内为参赛选手，队长额外拥有本组管理权限。
- **观众**：同样以姓名 + 验证码登录，名单外自动作为观众放行，只读浏览。
- **老师**：从 D老师、L老师、Z老师三选一，不需要验证码，只读查看并参与竞猜。
- 每个姓名对应一个独立账号；改码只让该账号的旧会话失效，不影响其他姓名及其会话。

### 2. 六大业务功能

1. **小组与名单**：首页只展示本组信息，队长可替换、删除本组成员，其他人只读。作用是让名单变更可控、可追溯。
2. **出场安排与发布**：每组仅有一份固定的 6 局出场阵容（混双 / 男双 / 男单 / 男双 / 混双 / 男单），由队长调整并发布；已发布须先撤回才能再改。作用是防止随意改阵容，并给赛程公布一个明确节点。
3. **赛程与对阵**：四组全部发布后才公开对阵，只显示「A VS B」，不暴露轮次、场地与安排细节；「正在进行」卡片显示实时比分与红蓝竞猜比例条。作用是在保护编排细节的同时让比赛进程透明可见。
4. **裁判计分台**：正式 6 局采用「追分」累计制，逐分流水记录，目标分依次为 15 / 30 / 45 / 60 / 75 / 90，支持撤销记分、切换比赛、结束本局。另有自定义对局（混双 / 男双 / 男单 / 女单）独立计分且不参与竞猜。作用是保证比分精确可纠正，同时不污染正式榜单。
5. **比赛竞猜**：支持冠军组别竞猜和正式赛每小局竞猜，开赛后锁定选择，撤销记分会同步修正预测。作用是提升参与感，并形成一套独立的竞猜积分体系（规则见下文）。
6. **积分榜单**：同时展示比赛积分榜与竞猜积分榜；四位队长确认比赛结束后冻结最终榜单、锁定比赛操作、结算冠军并弹出庆祝卡片。作用是产出权威成绩，防止赛后改动。

### 3. 支撑能力

- **实时同步**：数据写入时递增 `meta.revision`，前端轮询该版本号并在变化时自动刷新；本机、局域网、公网看到的是同一份数据。
- **权限与防篡改**：会话隔离、CSRF 校验、发布锁与确认锁共同保证「谁能改什么、什么时候能改」。
- **自定义对局隔离**：临时对局独立计分，不进入正式 6 局竞猜，也不影响榜单。

### 4. 运行底座

- `backend/`：Flask 单进程，负责路由、鉴权与全部比赛规则。
- `frontend/`：Jinja2 模板 + 原生 CSS / JavaScript，无打包步骤。
- 数据落在项目内 `.local/match.db`；公网通过 Cloudflare / ngrok 隧道转发回同一个后端。

**业务闭环**：名单 → 排阵发布 → 赛程对阵 → 裁判逐分计分 → 竞猜结算 → 双榜排名 → 四队长确认 → 冠军锁定庆祝。

## 环境

- Python 3.10 或更高版本
- 依赖见 `requirements.txt`（Flask）
- Node.js（仅运行前端脚本测试时需要）

## Windows 启动

双击 `start.cmd`，启动脚本会检查并安装 Flask，然后访问：

<http://127.0.0.1:8768>

也可以手动启动（从项目根目录执行）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe backend/app.py
```

可通过环境变量 `HOST` 和 `PORT` 调整监听地址与端口。

## 公网入口

运行 `start-public.cmd`，默认通过 Cloudflare 临时隧道转发到本地服务；也可运行 `start-public.cmd --tunnel ngrok` 使用 ngrok，该方式需要自行配置 `.local/ngrok.yml`，固定入口设置见 `backend/public_tunnel.py`。

本机、局域网和公网入口共用同一个后端与数据库，公网脚本会复用已运行的本地服务，不会启动第二份后端。

## 后台管理

入口在**登录页面右上角**的「后台管理」，点击后访问 <http://127.0.0.1:8768/admin/>，使用独立的管理员账号登录（默认 `admin` / `admin123`）。后台有独立的登录会话和 CSRF 校验，但**操作的是前台比赛系统使用的同一批真实数据表**，每次修改都会让在线页面自动刷新。

**比赛数据管理**：直接读写 `matches` 表，数据表格展示前台赛程真正使用的比赛名称、比赛时间、参赛对象、实时累计比分和状态。支持关键词搜索、按状态筛选、分页，以及新增、编辑、删除。比赛名称 / 时间 / 状态可直接改；**比分由裁判逐分计分产生，只展示不提供后台改分**，以免与计分流水和最终榜单不一致。删除比赛会同时清除其计分记录。

**账号管理**：直接读写 `players`、`teachers` 表，管理真实的 25 名队员和 3 位老师。可查看、搜索（姓名 / 组别），按角色（队长 / 队员 / 老师）和启用状态筛选，编辑姓名、组别、性别、队长身份与排序，并启用 / 禁用或删除。禁用后该姓名立即无法登录前台，已登录会话也会失效。

后台登录账号保存在独立的 `admin_users` 表，不占用前台姓名；表单提交前会二次确认，操作成功或失败均有明确提示。

## 数据与账号

首次启动自动生成 `.local/match.db` 和 `.local/secret_key.txt`，并写入 `backend/db.py` 中的初始分组名单。后续名单、安排及计分以数据库为准。

选手 / 观众使用姓名和个人四位验证码登录，初始验证码为 `1234`，可在登录后修改；老师入口按上述规则选择身份登录。

`.local/` 包含运行数据、密钥、隧道工具与备份，已由 `.gitignore` 排除；虚拟环境、缓存和本地工具状态同样不上传。需要保留现有比赛进度时，请另行备份 `.local/`。

## 比赛竞猜

导航中的「比赛竞猜」支持冠军组别竞猜和正式赛每小局竞猜；开赛后锁定选择。小局成功条件为从该局起始比分算起，率先新增十五分（继承分不计入），按逐分流水判定，裁判确认本局结束后结算。撤销记分会同步修正预测结果。所有人基础分为 1分；猜中得基础分 + 对方竞猜分数之和 ÷ 己方竞猜人数，猜错 0 分。冠军猜中加 5 分，在四组队长确认比赛结束后按保存的最终榜单结算；并列冠军组的竞猜均视为猜中。积分榜单新增竞猜记分并自动更新。

赛程「正在进行」卡片下方以红蓝条显示双方竞猜分数总和比例（左红、右蓝）；参与该小局竞猜的用户还会看到预测成功的预计得分，结束后显示个人结算结果。没有竞猜记录的小局不显示比例条。

更新后重启服务即可自动补建竞猜数据表，保留当前比赛数据。自定义对局继续按原规则计分，不参加正式小局竞猜。

## 比赛结束确认与冠军庆祝

积分榜单底部显示四组确认状态，仅各组队长可点击本组「比赛结束确认」。进行中的对局需先由裁判结束。比分、阵容或名单发生变化会使旧确认失效。四组确认同一版本后，保存最终榜单与冠军完整名单，锁定比赛操作，按胜场、净胜分确定冠军并统一结算冠军竞猜 +5 分；并列第一按并列冠军处理。所有在线页面会收到金色冠军庆祝弹窗，列出冠军组全体成员；每位用户每次比赛仅自动展示一次，关闭后按账号持久保存记录，切换页面、刷新、重新登录或更换设备后均不再自动弹出；榜单底部仍可主动再次查看。

竞猜积分榜按「总积分降序 → 最高单次得分降序 → 猜中次数升序 → 竞猜局数升序 → 姓名字符顺序」排列。最高单次得分仅取已结算小局竞猜的最高所得，不包含冠军竞猜加分；竞猜局数包含小局与冠军竞猜（含待结算），最多 36 小局 + 1 次冠军竞猜 = 37 次，猜中次数保留小局与冠军竞猜的累计统计。新统计由原有竞猜记录推导，无需清理比赛数据。
